What they are

dash-utils.css is an optional file of about 3,600 small classes, each setting one thing: flex, gap-3, p-4, text-muted, md:grid-cols-3. Link it after dash.css and a page can be laid out with no <style> of its own. The names are Tailwind's wherever the kit allows, so what you know carries over.

<link rel="stylesheet" href="dash.css">
<link rel="stylesheet" href="dash-utils.css">

There is no build step: the file is a fixed set (220 KB, 26 KB gzipped), written from the kit's tokens by tools/utils.mjs. The values are the kit's own, so a utility page and a component page look like one site.

A utility beats the kit

class="btn px-8" or class="panel p-0" does what it says, though the kit's own rules have two or three classes. Every utility is written .p-0:not(#\#): the :not() matches every element but counts as an id, so it outranks the kit without !important. A style="", the hidden attribute and !important rules (the kit's .hide-sm, say) still win. When the page's own CSS must beat a utility, use an id or !important there.

States

A prefix applies a class in a state: hover:bg-soft, focus-visible:ring-2, active:scale-95, disabled:opacity-50. hover: applies only where hovering is real (not on a touch screen). group-hover: applies when a parent with the class group is hovered; the kit's grouped table rows (tr.group) count too. Each group page says which of its classes take which prefix.

Widths

The widths are the kit's own: sm: from 641 px (past the kit's phone layout, 640 px and below), md: from 901 px (past its smaller-screen layout), lg: from 1024 px and xl: from 1280 px. As in Tailwind, a class without a prefix works at every width and a prefixed one from that width up. max-sm: and max-md: work up to the kit's two widths, as .hide-sm and .stack-md do. These differ from Tailwind's numbers on purpose: a page switches where the kit's components switch.

Dark and print

Colours are the kit's tokens, so bg-card text-muted border-line follow light and dark by themselves. dark: is for the few things that should differ, like dark:hidden on a light-only picture; it follows the system setting unless the page is set to light, and data-theme="dark", the same two ways the palette does. print: applies when printing (print:hidden on buttons).

Names the kit already uses

  • grid is the kit's grid: display grid with a 14 px gap and var(--cols, 2) columns. With grid-cols-* and gap-* it works like Tailwind's. sm:grid and the other prefixed forms are plain display: grid.
  • grow is the kit's flex: 1; min-width: 0. invisible and sr-only come from dash.css and mean what they do in Tailwind.
  • table, ring and outline are kit pieces, so there is no plain table, ring or outline utility: use ring-2 or outline-none.
  • On a .btn, block is the kit's full-width button; on .stats, fixed is the kit's fixed column count; on a .table, sticky is its sticky header. Everywhere else they are display: block and position: fixed or sticky.
  • No arbitrary values (w-[37px]): with no build step there is nothing to write them. Use the page's CSS, a style="", or a custom property the kit reads (--cols, --lines, --stat-min…).

Adding it to a page

  • Before adding the file to an existing page, look for classes in the page's own CSS with the same names (hidden, flex, border, truncate…): they would get the utility as well.
  • Pages with a strict style policy can use every utility: it's a stylesheet, not style="".
  • A page that must be one file adds <style id="dash-ui-utils"></style> after <style id="dash-ui-css">, and tools/paste.py fills it too.
  • To change the set, edit tools/utils.mjs and run node tools/utils.mjs (or npm run utils), then the tests. These docs list every class from the same script.
