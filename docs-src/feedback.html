Toasts

Dash.toast(message, { tone, ms, action, onAction }) is a short message at the bottom of the window that goes away on its own. With action: 'Undo' it has a button and stays six seconds. Screen readers hear it. Toasts and notices show above an open modal too.

Notices

Dash.notify({ key, title, status, text, tone, onClick, ms, max }) is an alert in the corner that stays until it's closed (or for ms). A second notice with the same key replaces the first, so a repeating alert doesn't pile up; Dash.notify.dismiss(key) takes it away. onClick makes it a button. On a phone, the newest two show.

The live status

.live says whether the page's data is current: data-state is on, stale, off or connecting (its dot pulses). Dash.live(el, state, text, title) sets it, and Dash.poll(fn, ms, { live }) keeps it right by itself: Live while answers come, stale when they stop, the error when one fails.

Flashing a change

Dash.flash(el) (or the .flash class) briefly highlights a value that just changed, so the eye finds it.

Hidden addresses

Dash.maskIps(text) escapes the text and blurs each IPv4 address in it, so they stay out of screen shares; a click or Enter on one shows every copy of that address on the page (.ip.shown). Dash.hideIps(text) writes (IP hidden) instead, for tooltips.

Hidden values

An eye in the top bar lets the reader hide amounts, names or account numbers before a meeting or a screenshot. While they are hidden the real ones aren't in the page at all: Dash.mask(text) writes a fixed blurred stand-in, so there is nothing to select, copy or find, and its length says nothing. The choice is remembered in this browser, and other open tabs follow it.

Balance
  • Dash.mask(text, { html, as, label }): the text (escaped), or the stand-in. html: true takes a builder's markup; as is the stand-in's text (000.00) and label what a screen reader hears (hidden). Nothing to hide (empty, or —) shows as it is.
  • Dash.mask.text(text, as): plain text for a title, a label, a chart's tooltip or a toast: the text, or as while values are hidden.
  • Dash.privacy.onChange(fn): draw again when the reader hides or shows them; it returns a function that stops it. Dash.table does it by itself for columns with private: true (or the stand-in's text).
  • The eye: Dash.privacy.button('balances'), or an empty <button class="icon-btn" data-privacy="balances"> in the page: "Hide balances", then "Show balances". A data-privacy button with its own words keeps them and is pressed while values are hidden. From code: Dash.privacy.on, .set(true), .toggle().
  • A text box with data-private shows dots until the reader clicks or types in it (Tab alone doesn't), and again when they leave it. The dots are only a look: the value is in the box.
  • It hides values from people looking at the screen; the page still has them. Keep the real ones out of title, data-key and data-copy yourself. Dash.table's CSV holds them. Hiding drops a text selection and an open tooltip; a toast or a notice that names a value is the page's to dismiss, in onChange.

The sign-in page

Put .login-page on the body and a form.login in it: a title, a .lead line, the fields, a btn primary block and a .note under it. Dash.config.loginUrl sends any request that comes back 401 there.
