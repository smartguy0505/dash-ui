A table from its columns

Dash.table(el, { columns, rows, sort, perPage, key, onRow, … }) draws a whole table: sortable headers, cells, a pager if asked, and cards on a phone. Give it columns once, then .update(rows) whenever the data changes; it redraws with Dash.render, so a refresh keeps the reader's place.

Columns

FieldWhat it does
key, labelThe row's field, and the header's text.
num: trueRight-aligned, sorted as a number. unit goes after the label (ms stays lower case).
main: trueThe column that titles each card on a phone.
value: (row) => …What it shows and sorts by, when that isn't row[key].
format: (value, row) => textText for the cell (escaped).
html: (row) => markupMarkup from a builder (Dash.pill, Dash.ago, Dash.bar…), not escaped.
sort: false, firstDir: 'asc'A column that doesn't sort; one whose first click sorts up (names, latency).
private: trueHidden while the reader hides values; a text is the stand-in to show instead of 000.00. Rows keep their order, and the CSV its values.
title, clsA tooltip on the header; classes on its cells.

Options and the handle

  • sort: { key, dir, store }, remembered under store; perPage (0: no pager; give one from about a thousand rows, as every refresh writes all that show) and sizes; noun for "of 23 servers".
  • key (a field or a function) gives each row a data-key, so a refresh keeps the focused row. rowClass: (row) => 'marked bad', empty text, filter: (row) => keep?.
  • cls sets the table's classes ('stack' by default), wrap: true makes it its own card, onRow(row, event) runs on a click or Enter on a row (not on a button or link in it).
  • select and expand: rows the reader can pick and open.
  • The handle: .update(rows), .filter(fn), .count (rows shown), .csv(rows) and .download(name, rows) (every row that passes the filter, unless you give them some), .goto(page), .sort.

Rows to pick

select: true puts a box on every row, one in the header, and a bar under the table while any are picked. Give it { actions } for something to do with them. It needs key.

  • What is picked is kept by key: through a refresh, sorting, paging and a search, until the row leaves the data. The bar counts the ones that aren't in sight (“2 not on this page”), and an action gets them all, so name them before doing something that can't be undone.
  • The header's box picks this page; when there is more, the bar offers every row that passes the filter. Shift-click picks a range. The whole cell is the box.
  • can: (row) => … says which rows may be picked. actions: [{ label, tone, primary, run: (rows, table) => … }]: while a promise run gave is pending its button is busy, and an error it throws shows as a toast. onChange(rows) runs when the picked rows change.
  • table.selected is the rows. table.select(keys) picks those and no others, table.select((row) => …) the rows that pass, table.select([]) none.
  • On a phone, where the cards have no header, a box above them picks them all.
  • A screen reader hears each box as “Select” and the row's name: the main column's text, or rowLabel: (row) => text. While that column is hidden by the reader's eye it is the row's number.

Rows that open

expand: (row, box) => markup gives each row a button that opens its details under it. Without onRow a click anywhere on the row does it too. It needs key.

  • Give markup, an element, or nothing when you draw in box yourself. box stays the same element while the row is open, so a chart or a table in it keeps its place when the data is refreshed. Markup that comes out different is drawn anew, and what the reader typed, ticked or chose in it stays, as long as each field has an id, a data-key or a name of its own (once it is saved, empty the field yourself). Draw on every update as above, or keep what you made: (box.jobs ||= Dash.table(box, { … })).update(row.jobs).
  • Give a promise for details that have to be fetched: expand: async (row) => render(await Dash.api('/jobs/' + row.id)). The row says “Loading…”, then shows the answer, or the error with a button to try again. It is asked for when the row is opened, and again on table.redraw(), not on every update. An answer that comes after the row was closed is dropped.
  • expand: { draw, can, one }: can: (row) => … says which rows have details, one: true keeps one open at a time.
  • table.expanded is the open rows; table.expand(key) opens one, table.expand(key, false) closes it. A row stays open through a refresh, sorting and paging, until it leaves the data.
  • A table in the details is its own: its headers, pager and boxes don't reach the one around it.

Tables by hand

A .table inside a .panel gets a rounded header strip; in a .table-wrap the table is its own card and scrolls sideways if it must. Sortable headers are <th aria-sort="descending"><button data-sort="key">, which Dash.th(label, key, sort, { num, unit, title, cls, mark }) writes. th.num and td.num align right. .table.compact puts 8 px between columns instead of 12 (--cell-x).

Dash.sortBy(rows, key, 'asc' | 'desc') sorts a copy: numbers as numbers, text as a person would (web-2 before web-10), blanks last. Dash.sorter({ key, dir, store, firstDir }) keeps the state for your own headers: .toggle(key), .apply(rows, getters).

Row states

  • tr.marked: a bar on the left and a tint, blue unless a tone is added (marked bad). tr.dim: faded.
  • tr.sub: smaller rows that belong to the one above. tr.group: a heading row. tr.cut: a dashed line, for "below this, not paid".
  • tr.click: a pointer, for rows that open something. .empty-row: one row saying there is nothing.
  • td.actions (and th.actions): a row's buttons at the right, as narrow as they are; on a phone's card they sit in its top corner (--actions-w keeps the title clear of them).

On a phone, and long tables

.table.stack turns each row into a small card on a phone. Give each td a data-label; the td.main cell is the card's title. .stack-md does it from 900 px down instead, for a table too wide for a tablet. Dash.table does all of this by itself.

.table.sticky inside a .table-wrap.open keeps the header under the top bar while a long page scrolls (.open lets the header out of the card's own scrolling).

Working with rows

  • Dash.sum(rows, key): a column's total (blanks count as 0). Dash.groupBy(rows, key): an object of the rows by a key, in the order first seen (key may be a function).
  • Dash.csv(rows, columns): rows as CSV; columns as for Dash.table ({ key, label, value }) or plain keys. Text that a spreadsheet would read as a formula gets a leading '; text that is just a number stays a number. Dash.download(name, content) hands the reader a file.
const byRegion = Dash.groupBy(servers, 'region');        // { 'eu-west': [rows], … }
Dash.download('servers.csv', Dash.csv(servers, ['name', 'region', 'cpu']));
