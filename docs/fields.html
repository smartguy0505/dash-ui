Richer fields

Numbers with − and +, passwords that can be shown, codes, suggestions, tags, selects that can be searched, dates, ranges, ratings, and text that is edited in place.

Numbers with − and +

Dash.number({ label, name, min, max, step, value, unit, hint, required }) writes a number box with a button on each side. A button that is held goes on, each is off at its end, and change fires once when it is let go. By hand: <div class="num-field"> with a .btn that has data-step="-1", the .input, and a .btn with data-step="1". Keyboards and screen readers use the box itself, with the arrow keys, so the buttons are no stop for Tab.

Passwords that can be shown

A button with data-peek beside a password box shows what is typed, and hides it again when pressed once more or when the form goes out. Give it data-peek="id" if the box isn't in the same .input-group or .field. Its words change between Show and Hide; with an icon inside, only aria-pressed does.

Codes

Dash.code({ label, name, length, letters, submit }) is a box for the code from a message, drawn as one box per character. It is a single field, so a paste (with spaces or dashes), a phone's suggestion and a screen reader all work. A press goes into the box that is pressed, and a digit takes the place of the one in the lit box; arrows go from box to box, and Backspace takes a wrong one out. Once it is full it fires dash:code with the code in detail; submit: true sends its form, and letters: true takes letters too.

Suggestions

Dash.combobox(input, { options, onPick }) gives a text box a list of suggestions that narrows as the reader types. Arrow keys move through it, Enter or a click picks, Escape closes the list (only the list, inside a dialog too), and the box keeps the focus throughout. The typed words are bold in each suggestion.

  • options: strings, or { value, label, sub } (sub is a second, quieter part), or a function (query) => list or a promise of one, for a server search. Answers that arrive after the reader typed on are dropped. debounce (150 ms) is how long typing has to pause first.
  • strict: true: on leaving, text that is no suggestion is put back to the last pick (or emptied); a box the reader empties stays empty.
  • max (50) suggestions, minChars before any show, empty for the line when none match.
  • It returns { value, set(value), close(), destroy() }; value is the picked option while the box still shows it, else null. It's an ARIA combobox: the box has role="combobox", the list listbox, the active suggestion aria-activedescendant.

Tags

Dash.tagbox(input, { options, max, strict, allow, onChange }) makes a text box take several things. Enter or a comma adds what is typed, a pasted list adds all of it, Backspace in the empty box takes the last one away. The form sends one field of the input's name per tag; Dash.form gives them as a list.

  • options: suggestions, as for Dash.combobox (a list, or a function that looks them up). strict: true takes only those.
  • allow(text) returns true, or why not as text; the text stays in the box. max is how many there may be.
  • It starts with the box's own value (a, b, c) or value: [...], and returns { value, set(list), add(text), remove(text), destroy() }.

Selects that can be searched

Dash.multi(select, { noun, placeholder, search }) puts a button over a <select> that says what is picked and opens a list: boxes to tick for a <select multiple>, one to pick otherwise, with its <optgroup>s as headings and a search box from eight options on. The select stays the field: its label, its change event, a form's reset and Dash.form work as before, and without the script it is the select it was. .update() after the page changes what is selected, .open(), .destroy().

Dates

Dash.datepicker(input, { min, max, onPick, firstDay }) puts a calendar button in a date box. Dates are YYYY-MM-DD, what <input type="date"> sends. The calendar opens on the box's date (or today): arrows move a day or a week, Home and End go to the week's ends, PageUp and PageDown a month (with Shift, a year), Enter picks and Escape closes. Days before min or after max can't be picked. Typing works too: a short date like 2026-3-7 is written out, and one that doesn't exist is marked aria-invalid. Weeks start on Monday; firstDay: 0 starts them on Sunday. Month and day names are in the reader's language.

It returns { value, set(day), open(), close(), destroy() }; value is the box's date if it's a real one in range, or null.

From and to

Dash.range({ label, name, min, max, step, from, to, unit }) is a slider with two ends, where neither passes the other. A form sends name_from and name_to; both fire input and change as any slider.

Ratings

Dash.rating({ name, value, max, label }) is a group of radio buttons drawn as stars; a form sends the number. With readonly: true it shows one, parts of a star too, and text puts words after it. size: 'sm' | 'lg' and tone set how it looks.

Edit in place

Dash.inline(el, { value, label, onSave }) shows text that becomes a box when it is pressed. Enter or Save saves, Escape puts it back. onSave(value) may return a promise; if it fails, or gives false, the box stays open and says why.

  • type: 'text', 'number', 'email' … or 'select' with options; attrs: { min: 1, maxlength: 40 } go on the box and are checked.
  • check(value) returns what is wrong as text. format(value) is how it reads, empty what stands there for nothing.
  • It returns { value, set(value), edit(), cancel(), destroy() }.
