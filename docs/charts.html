Charts and progress

Bars, meters, legends, column charts, donuts, gauges, sparklines, lanes, heatmaps, days and progress.

Bars

Dash.bar(frac, tone) is a bar filled to frac (0 to 1); .bar.thin is thinner and .bar.tinted has a tinted track. Dash.meter(frac, tone) is the small one for a top bar. Dash.split(parts) shows the parts of a whole, each { value, tone, label }. .share puts a bar and its percentage side by side.

Legends

Dash.legend(items, { list, button }) names the colours of a chart: each item { label, value, tone }, a swatch, the name and the value in b. list: true puts one per line (an item with 0 fades, .zero); button: true makes them buttons, for a legend that filters.

Horizontal bars

Dash.hbars(rows, { max, format, button }) is a list of bars with their names and values, for a top ten: each row { label, value, tone, text, key }. max sets the full length (the largest value otherwise), format writes the values. --hb-label and --hb-value set the two columns' widths.

Column charts

Dash.bars(points, { height, ticks, labelEvery, minorEvery, format, max, read }) is a column chart with a value axis. A point is { label, value, tone, title, partial }; partial marks one still running (this hour), and parts: [{ value, tone }] stacks a column, the first part at the bottom. read: 'Total 2.1M' adds a line above it that shows the hovered column's title. Labels marked minor (by minorEvery) hide in a panel under 480 px. Dash.niceMax(n) is the round axis top it uses (87 → 100).

Line charts

Dash.lines(el, series, options) draws values over time, one line per series, on one axis. A series is { label, points }; a point is [time, value] or { t, v }, with a time as Dash.time reads them. Points needn't be evenly spaced, and a value that isn't a number leaves a gap. Move over the chart, drag a finger, or focus it and use the arrow keys.

  • Up to four series get the series colours in order (.series-1 to .series-4; the tokens are --series-1…). They were picked by measure, so that every pair can be told apart in light and dark, by colour-blind readers too. tone: 'bad' is for a colour that means something. Past four a line is grey: use two charts.
  • A series can also be dashed: true (a forecast, last week), filled with area: true, and have its own gap.
  • min is 0 unless the data goes below it; min: 'auto' fits the data, a number fixes it, and max too. ticks is about how many steps the axis has, format writes the values, yFormat the axis when it needs shorter ones.
  • from and to set the range (the data's ends otherwise); a line that crosses them is cut there. gap (in ms) breaks a line at a longer silence. refs: [{ value, label, tone }] draws limits across. when: (t) => text writes the readout's time.
  • private: true hides the numbers with the reader's eye; the shape stays.
  • For a screen reader the chart is a slider: it hears each point as the arrow keys move, and a summary before it. label names it.
  • The handle: .update(series, options) (or call Dash.lines again on the same box: the reader stays at their point), .redraw(), .csv(), .download(name). Dash.lines.html(series, options) is the markup alone, with no crosshair. A few thousand points per series is fine; send averages for more.

Donuts

Dash.donut(segments, { center, sub }) is a ring of { value, tone, label } segments with a number in the middle. Put it in .donut-wrap beside a Dash.legend(…, { list: true }).

Gauges

Dash.gauge(frac, { name, sub, tone }) is a half-circle gauge. With no tone it goes from ok to warn at 0.7 and bad at 0.9. .gauges lays a few side by side.

Sparklines

Dash.spark(values, { tone, height, area, labels }) is a small line of a trend, with an area under it unless area: false, a dot on the last value, and labels under it (['24 h ago', 'now']).

Lanes

Dash.lanes(el, rows, { from, to, ticks, axis, nouns, labelWidth, empty }) draws what happened when, one lane per thing, over the last 24 hours unless from and to say otherwise. A row is { label, sub, spans: [{ from, to, tone, title }], marks: [{ at, tone, title }] }; a span with no to is still going. Spans are cut at the edges, titles (or the times) are tooltips, and each lane gets a sentence for screen readers. It needs no inline styles, so it works under a strict style policy too.

Heatmaps

Dash.heatmap({ rows, cols, values, label, min, max, format, show, every, tone }) shows how much there is in a grid: a real table, with a shade per cell. One hue says how much: the least is close to the panel, the most is the furthest from it, in five steps that stand out from each other in light and in dark. null is a gap, which is drawn differently from nothing. Pointing at a cell says its row, its column and its value.

show: true writes the values into the cells, on paler shades they can be read on. every: 3 names every third column (a screen reader gets all of them). min and max fix the ends, so that several have the same shades; legend: false leaves the legend out. The steps are the tokens --heat-1 to --heat-5: how much of the tone is in each.

Days

Dash.days(points, { weeks, to, label, noun, tone, max, first }) is a square per day and a column per week, for the last 26 weeks unless weeks and to say otherwise. A point is { date: '2026-11-25', value } or { t, value }; several of one day add up, and a day without one is 0. Weeks start on Monday (first: 0: Sunday). What it adds up to and the busiest day are said to a screen reader.

Progress

Dash.progress(frac, { tone, label, value, lg, title }) is a progress bar with role="progressbar" and its value. label puts a line above it (.progress-head) with the share on the right, or value in its place ("6.2 of 10 GB"); lg: true is thicker. Dash.progress(null) is one that runs until the amount is known (.indeterminate; a steady bar for readers who turn motion off). Dash.progressCircle(frac, { tone, size, text, label }) is the round one, an SVG.

Under a strict style policy

A page served with Content-Security-Policy: style-src 'self' drops every style="" in its markup, and the builders that size things (Dash.bar, meter, split, hbars, bars, lines, spark, progress) write sizes that way. On such a page, set Dash.config.csp = true before drawing anything: they then write their numbers as data-css-* attributes, and the kit sets them through the CSSOM, which the policy allows. It does so at once wherever the kit puts markup in (Dash.render, popups, modals) and before the next paint for markup the page puts in itself; Dash.applyStyles(el) does it at once. Only numbers are set, and only on the kit's own pieces.
