Getting started

Two files and a page: what dash-ui is, how to add it, and how a page is put together.

What it isAdd it to a pageA first pageWhat's in the kitWhat every piece does

What it is

dash-ui is a small kit for dashboards and admin pages: one stylesheet, dash.css, and one script, dash.js. There is nothing to install or build. A page links the two files, uses the kit's classes in its HTML, and calls Dash helpers for the parts that move: tables that sort, charts, toasts, modals, popups, polling.

  • Components: panels, cards, stat tiles, tables, forms, buttons, menus, tabs, charts, modals and more, each in light and dark, from a phone to a wide screen.
  • Builders in dash.js write a component's HTML from data, with every value escaped: Dash.pill('Healthy', 'ok'), Dash.bars(points), Dash.table(el, { columns }).
  • Utility classes, in the style of Tailwind, in an optional third file, dash-utils.css: flex gap-3 md:grid-cols-3 p-4 text-muted. They are made from the same tokens, so they match the components.

Every page in these docs shows each piece live, with its code under it. Copy takes the code, Phone shows it at a phone's width, and the theme button shows it in the other theme.

Add it to a page

Copy dash.css and dash.js next to your page, or point at them where they are served, and link them in the head. dash-utils.css is optional and goes after dash.css.

<link rel="stylesheet" href="dash.css">
<link rel="stylesheet" href="dash-utils.css">   <!-- optional: the utility classes -->
<script src="dash.js"></script>

The script goes in the head so that the page's own scripts can use Dash anywhere below it. It waits for the page itself where it needs to.

One file

For a page that has to be one file (a report sent by mail, a page a server writes out), tools/paste.py page.html puts the kit into the page's <style id="dash-ui-css"> and <script id="dash-ui-js"> blocks, and the utilities into <style id="dash-ui-utils"> if the page has one. Run it again after updating the kit.

Versions

The first line of each file names its version (/* dash-ui 1.9.0: …), and Dash.version says it in a script. Versions only add things: a page that works with an older copy works the same with a newer one, so a page can update when it likes.

A first page

A top bar, then a .page holding the content: here a row of stat tiles and a panel with a table built from its columns. Data would come from Dash.poll and Dash.api; the rows are written in so the example stands alone.

On a phone the table's rows become small cards, and the stat tiles go two across. Nothing on the page has to ask for that.

What every piece does

  • Escapes what it's given. A builder writes text as text, so a name with < in it shows as a name. Links that would run script (javascript:) become #.
  • Works with a keyboard and a screen reader. Menus, tabs, popups, modals, the drawer, the suggestions and the calendar move with the keys a reader expects, say what they are, and give the focus back when they close.
  • Keeps the reader's place. Dash.render redraws a part of the page without losing what is being typed, the focus or the scroll.
  • Fits a phone. Nothing scrolls sideways; tables become cards, the sidebar a drawer, tile rows two across.
  • Follows the reader's settings: dark mode, less motion and forced colours.
