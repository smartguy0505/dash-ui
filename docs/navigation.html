A sidebar

.shell puts a .sidebar beside the .content. The sidebar holds .side-head labels and .nav-item links or buttons. An item has an optional .nav-icon, a .nav-main with a .nav-name and a .nav-sub, and a .nav-meta on the right. aria-current="page" marks where the reader is; .attn with a tone tints one that needs a look.

A button with data-toggle-side folds the sidebar to a 64 px rail of icons (.shell.collapsed) and back; the choice is remembered (Dash.config.sideKey), and document gets a dash:side event with e.detail.collapsed. --side-w sets the sidebar's width.

Groups in the sidebar

Dash.nav(el, items, { current, store, onPick }) writes a sidebar's links from data. An item is { label, href } (or a key instead of a link, for a button), with an optional sub, icon and meta (HTML), badge and tone. { heading } is a label between them, and an item with items a group that opens and closes. current is the address or key of the page the reader is on: its link is marked and its group open. store: 'name' remembers the groups they opened.

.filter(text) shows the links with the words, inside their groups and under their headings, and returns how many. .current(key) marks another page, .update(items) writes new links. Folded to the rail, a group shows its icon, and a click on it brings the sidebar back with the group open.

By hand, or from a server: a group is <details class="nav-group"> with <summary class="nav-item"> and a .nav-list of .nav-items, and it needs no code. Dash.nav(el, null, options) takes links that are already in the page and adds the rest, and Dash.nav.html(items, { current }) gives the HTML as text, in Node too.

The sidebar as a drawer

Add .offcanvas to the shell and, from 900 px down, the sidebar becomes a drawer over the page. The same data-toggle-side button opens it there (and still folds the rail on a wider screen). While it's open, the rest of the page is inert; Escape, a click outside it or a link inside closes it, and the focus goes back to the button. These docs use it: make the window narrow and press ≡.

Dash.side.open() and Dash.side.close() do it from code; open returns false on a wider screen, where there is no drawer.

Marking the section being read

Dash.spy(el, { offset, onChange }) follows the reader down a long page: of the links in el to parts of this page, the one to the part being read gets aria-current="location". A .nav-item, a .chip and a .link show it, and a list of links that scrolls keeps it in view. One that is clicked stays marked until the reader scrolls on. The sidebar of these docs is one: it shows where you are on this page.

offset is how many pixels under the top bar a part has to reach to count (24). .current is its id, .update() looks again after the page changed, and .stop() ends it.

Command palette

Dash.palette({ items, key, recent, placeholder, onPick }) is a box to find anything and do it, from anywhere on the page: key opens it ('mod+k': Ctrl+K, or ⌘K on a Mac). An item is { label, sub, group, icon, keys, words } with href or run(item); the ones with neither are told to onPick. Every word typed has to be in the label, the note under it, the group or words; those whose label starts with it come first. With recent (where to remember it) what was picked last comes first while nothing is typed. Press Ctrl K here: these docs have one.

items can be a function (query) => list, or a promise of one, to look things up: a slow answer says so, a late one is dropped. An item can open another palette. .open(query), .close(), .isOpen, .update(items), .stop(). Dash.keys('mod+shift+k') draws a shortcut as key caps ('g then s': one after the other), as the reader's system has them.

Tabs

.tabs is a row of buttons with data-value over panels with a matching data-tab. Dash.tabs(el, { value, store, hash, panels, onChange }) shows the chosen panel and hides the others; arrow keys move between tabs. store remembers the tab, hash: 'view' keeps it in the address (#view=list) so a link or a reload opens it, and panels says where the panels are when a page has two sets. It returns { value, set(v) }. A .count-badge in a tab holds a count.

Breadcrumbs

Dash.crumbs(items, { label }) writes where the reader is: { label, href } for each level, and plain text for the last, which is marked aria-current="page". A link that would run script becomes #. It's a nav named "Breadcrumb" with an ol, so screen readers announce it as a trail.

Steps

Dash.stepper(steps, current, { vertical, tone, label }) shows the steps of a task: those before current are done (a tick), the current one is marked aria-current="step", and a step { failed: true } is red, with a "!". Screen readers hear "done" and "failed" with the names. A step is text or { label, sub, failed }; current past the last means all are done. On a phone only the current step's name shows, and the others are still read out. vertical: true stacks them, with the sub line under each name.

Pages of rows

Dash.paginate(rows, page, perPage) cuts one page out of the rows and says where it is ({ rows, page, pages, total, from, to, perPage }). Dash.pager(that, { noun, sizes }) writes the bar under a table: "21–40 of 140 servers", a rows-per-page select (data-per-page) and page buttons (data-page). Dash.pageItems(page, pages) is the list of page numbers it shows, with gaps. Dash.table does all of this itself.
